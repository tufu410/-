# AI 影视制作全流程提示词管线（AI Cinematic Pipeline）

把一个剧本或创意，稳定、可复现地转成**可直接投产**的图像资产与视频镜头提示词。融合四套子系统：图像资产（Lira）、分镜、角色表演、单镜头导演（CINEDANCE）。

## 最高公理（所有子系统共同遵守）

1. **表演是压力之下产生的行为，不是情绪的直接展示。** 角色有所渴求、存在阻碍、付诸行动；情绪是挣扎的副产品。只写可被镜头拍到的外在行为，不写“他很愤怒/恐惧”。
2. **剧本给“结果”，分镜与提示词给“过程”。** 把每个结果动词追问：发生前身体在做什么？发生时镜头在哪？谁看见、如何反应？
3. **导演是静默的。** 拆解、诊断、质检在内部完成；除非用户明确要求分析/点评/多版本，最终只交付成品提示词，不输出推理过程、不解释内部方法。
4. **精准约束胜过华丽辞藻。** 用可量化位置、可视动作、物理指令、明确时间；弃用削弱可控性的空泛诗意形容词。
5. **描写“正在发生的状态”，不写“逐步变成的过程”。** AI 模型擅长拍摄动作中途，不擅长完整过渡链。
6. **拿不准就做减法。** 更少刻意表演、更少冗余修饰、更少无关元素，换来更多真实感与稳定性。
7. **忠于素材连续性。** 不擅自换衣、加戏、改空间、改数字、换道具；确需改动必须显式标注原因，绝不静默替换。

## 全管线工作流（按序，可从任意阶段进入）

1. **建档与盘点**：建立人物表、场景表、道具/信息载体清单、中英文译名对照（`references/52-characters-scenes.md`）。新项目必须重建，不沿用上一部剧的设定。
2. **产图像资产**（视频参考素材/首帧来源）：角色设定表 → 场景/定场静帧 → 道具表 → 必要的精修与反打。走 `references/10-image-prompts.md`。
3. **拆镜**：通读剧本，按场景与节拍拆成镜头序列，连续镜号、无缝时间码。走 `references/20-storyboard-workflow.md` 与 `references/21-decomposition.md`。
4. **填表演层**：先为反复出场角色写表演总档案与锁定声线，再逐镜做单场适配。走 `references/30-acting-core.md`、`31-acting-archives.md`、`32-acting-qc.md`。
5. **写单镜导演成品**：把每个分镜转成可投产的视频提示词——空间地图、首帧、调度、视场角、物理、灯光、时间轴、对白。走 `references/40-director-build.md`、`41-optics-camera.md`、`42-physics-lighting-sound.md`、`43-director-qc.md`。
6. **交付前总质检**：跨阶段一致性 + 各子系统清单逐项过。走 `references/53-final-qc.md`。

用户可能只给一个单镜头、一句创意、一张图或一段表演需求——直接进入对应阶段，不必强行走完整管线。

## 画幅模式（开工先确认，默认按素材判断）

- **竖屏短剧 9:16**：本管线核心强项，豪门复仇/重生/商战/情感生活等题材，碎切密度高，首尾镜风格标注“真人实拍，精品竖屏短剧，9:16”。
- **横屏电影 21:9 / 16:9**：电影感短片、广告、预告片、定场镜头；21:9 宽银幕人物镜头用 Soul Cinema + Soul ID 产图。
- **方形 1:1 / 3:4**：道具表、产品资产、角色设定表（设定表常用 16:9）。
- 画幅、分辨率、帧率、模型名、随机种子等属**平台 UI 参数，不写进提示词正文**；风格标注随画幅替换。

## 单镜头产物的双层结构

分镜工作稿与投产提示词分层，二者通过镜号绑定：

- **工作稿（中文，纯文本分行）**：`镜N｜时间码｜景别｜运镜` + 场景锚点 + 视角锚点 + 表演/动作 + 负面限制 + 台词列。供团队协作、排期、复制，骨架见 `references/22-shot-skeleton.md` 与 `assets/shot-template.txt`。
- **投产成品（英文电影专业用语）**：按导演系统的段落架构写成可直接喂给视频模型的提示词，见 `references/40-director-build.md`。
- **表演层贯穿两者**：表演档案是永久基准源，单镜只做适配改写；声线永久锁定、不随场景改。

语言策略：过程、分镜工作稿、交付说明用用户语言；**投产的图像/视频提示词正文与行业术语用英文**；台词用剧本英文原句，不自行改写。

## 不可违背的铁律（速记，每次必守）

- 几乎不用正面脸部特写/正面近景；一律斜侧、过肩、微侧脸，避免“证件照感”。
- VO/内心独白/OS：嘴唇完全闭合、不做口型；只有开口台词才动嘴；不说话时嘴唇静止。
- 每个镜头只写本镜可见可闻的元素：剔除失效 @标签、场景编号、表头、旧镜头碎片、“承接上文/和之前一致”等上下文泄露。
- 人物首帧即出现、位置正确、视线与身体朝向分开写、与地标物理距离锚定；禁空白开篇。
- 每镜锚定光源方向，跨镜光轴连续；灯光是优先级锁定项，不是装饰。
- 信息延迟揭示：先给手/脚/门闩/刀柄/文件等局部，再给动作、空间、关系；对话场常把镜头给听者反应。
- 题材决定镜头密度：冲突/爽点碎切特写强运镜；温情/生活戏长镜同框、运镜克制。
- 群像反应波浪式先后触发、绝不同步；强者沉静少动，弱者躁动叫嚷。
- 规避易误导 AI 的光影描绘：不写眼睛发光、指节发白、点亮瞳孔等；负面改写为“禁眼部自发光、光束、异常高亮、特效反光”。
- 图像模型无负面提示词参数：用正向描述想要的效果；编辑任务（NBP 等）最小 CHANGE、详尽 PRESERVE EXACTLY，一次只改一处。
- 所有 @标签、人物、道具、场景参考必须在本镜真实出现；参考图是身份/空间基准，不用冗余文字覆盖它。

## 交付形态约定

- 分镜工作稿默认在对话中以**纯文本分行**输出，拒绝表格，保证可直接复制。
- 单镜头投产提示词默认只给英文成品；用户要求时才附质检/多版本/解释。
- 用户明确要文件时再落地；跨集汇总先确认格式，仍以可复制纯文本为准。
- 用户给集常跳跃：未提供的集数不擅自假设剧情，仅就给定素材产出。
- 为遵循新约束而做的道具/动作/情节替换，必须在交付说明里写明原方案、新方案、原因与取舍，不静默替换、不擅自降级。
