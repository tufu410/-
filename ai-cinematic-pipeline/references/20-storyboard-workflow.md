# 20 · 分镜端到端工作流（Storyboard Workflow）

> 拆分镜时先读本文件。目标：把剧本稳定、可复现地转成标准化分镜工作稿，不遗漏、不擅自加戏。单镜字段规范见 `22`，拆镜规律见 `21`。

## 目录

1. 阶段 A：接收与消化（不抢跑）
2. 阶段 B：场景 / 人物 / 道具盘点
3. 阶段 C：参考图读取与超大图处理
4. 阶段 D：按节拍拆镜
5. 阶段 E：逐镜填充与时间码
6. 阶段 F：从工作稿到英文导演成品
7. 阶段 G：交付前自检与改动标注
8. 环境备忘（Windows / PowerShell / .NET）

---

## 阶段 A：接收与消化（不抢跑）

- 用户处于“喂范例 / 喂剧本”阶段时，**只学习、不总结、不生成**，等用户明确说“提炼 / 拆分镜 / 写提示词”再动手。
- 完整读取全部输入，不因格式麻烦而跳过；读不到先解决读取问题，不用印象或二手摘要代替。
- 识别剧本标准排版单元：
  - 场景表头：`场号 地点 日/夜 内/外`（如 `16-2 台球室 日 内`）。
  - 人物行：`人物：A B C`，界定本场允许出现的角色（负面限制据此控制人数）。
  - 动作行：常以 `△` 开头，是“结果式”描写，需在分镜里展开成“过程”。
  - 台词行：`角色（情绪/动作）：中文台词`，常跟一行 `Role(...) : English line`。
  - `VO`=画外内心独白；`OS`=画外音（电视主播、电话）；闪回标记 `【闪回】…【闪出】`。
- 核对中英文台词一一对应，记下每句英文原句（台词列必须用英文原句，不自行改写）。
- 确认画幅模式与风格标注：竖屏短剧首尾镜写“真人实拍，精品竖屏短剧，9:16”；横屏按项目替换为对应风格标注（如“真人实拍，院线级电影感，21:9”）。

## 阶段 B：场景 / 人物 / 道具盘点

为每集（或每场）建立三张内部清单，建档字段模板见 `52-characters-scenes.md`：

1. 场景清单：每个 `地点·日/夜·内/外` 一项；标注与前后场是否同景（同景保持空间结构、光线连续）。
2. 人物清单：本场实际登场者；身份、与主角关系、本场情绪起点与终点。反复出场者确认是否已有表演总档案（`31`）。
3. 道具 / 信息载体清单：把“口述信息”转成可拍道具（文件、电视新闻、白板、合同、沙盘、酒、血迹等，方法见 `21` 第 7 节）。

## 阶段 C：参考图读取与超大图处理

- 逐张读取参考图，分别记录三类信息：
  1. 空间结构：墙体、门窗方位、家具布局、通道与走位路线（保持“不偏离参考图”）。
  2. 人物形象：年龄、体型、发型、肤色、服装、配饰、气质（人物一致性）。
  3. 光线：光源方向、软硬、冷暖、反差、光斑形状、空气质感。
- 用户对“时间点 / 光线软硬 / 色调”的口头要求，优先级高于参考图默认光线（参考图偏白硬、用户要“早晨九点柔和、不白硬”，则按柔和暖光处理）。
- Read 图片限制：单边不超过 4000px、base64 不超过 5MiB。超限先处理：
  - 等比缩小到短边约 1000px、转 JPEG（约 200–400KB）通常即可读。
  - 竖长图先缩到宽约 1000；仍过大可裁上下两半分别读。
- Windows 无 Bash、可能无 PIL：用 PowerShell + .NET `System.Drawing` 缩放（脚本见本文件末尾）。

## 阶段 D：按节拍拆镜

- 先把每场切成若干“节拍（beat）”：一个节拍 = 一个可被观众感知的情绪/信息变化（与表演系统的节拍定义一致，见 `30` 第 2.4 节）。
- 再为每个节拍配镜头组。常用配比：
  - 一句 VO 常拆 3–4 镜：建空间 → 人/物关系 → 关键动作 → 伏笔/反应。
  - 关键动作固定三镜：预兆局部 → 执行全景 → 反应群像。
  - 揭示顺序：特写悬念 → 近景动作 → 全景空间 → 关系格局。
- 题材决定密度（详见 `27-style-density.md`）：
  - 冲突 / 爽点 / 刺杀 / 演讲：碎切、特写、强运镜，单镜可短至约 2 秒。
  - 温情 / 生活 / 关系戏：单镜 2.5–3.2 秒，双人同框、运镜克制、留白足。

## 阶段 E：逐镜填充与时间码

- 严格按 `22-shot-skeleton.md` 的七段骨架逐镜填写。
- 镜号全片连续（多场景不重置）。每集是否从 1 开始，以用户当集要求为准。
- 时间码起止精确到 0.1 秒，前后无缝、不断档不重叠。长集可用 `scripts/next_timecodes.py` 由每镜时长自动生成连续区间。
- 台词分配：
  - 开口台词：角色嘴部配口型，台词列写明情绪/动作与发声方式。
  - VO / OS / 内心独白：画面人物嘴唇完全闭合不动；标注“内心独白，嘴唇不动”。
  - 无台词：台词列写 `—`。
- 表演层：先确认角色本场的行动目标、阻碍、策略与节拍切换（`30`），把表演写成可拍行为与眼神动态（`31`），不直接写情绪。

## 阶段 F：从工作稿到英文导演成品

- 中文七段工作稿用于协作与排期；要喂给视频模型时，逐镜转成英文导演成品（架构见 `40-director-build.md`）。
- 转换要点：场景锚点→场景空间地图与灯光锁定；视角锚点→机位/视场角/构图；AI视频提示词→动作时间轴 + 表演段（英文）；负面限制→按需改写为行内局部锁定（视频模型支持负面时保留十类清单，见 `51`）。
- 单镜头默认输出英文成品；批量分镜可先交中文工作稿，再按用户要求逐镜或选镜出英文成品。

## 阶段 G：交付前自检与改动标注

逐项核对（发现即改，改后重算受影响镜头时间码）：

- [ ] 镜号连续、无重复无跳号；时间码逐镜咬合、无断档无重叠。
- [ ] 每镜七段齐全；首尾镜含与画幅匹配的风格标注。
- [ ] 台词与剧本逐句对应、无遗漏、未擅改；VO 镜头明确“嘴唇不动”。
- [ ] 几乎无正面脸部特写/正面近景；以斜侧、过肩、微侧脸为主。
- [ ] 每镜光源方向明确，跨镜光轴连续；人物走位与冷暖光区一致（`50`）。
- [ ] 未出现易误导光影词；负面含“禁眼部自发光、光束、异常高亮”（`50`/`51`）。
- [ ] 人数受控：仅本场人物行允许的角色，无新增、无人物复制、无多余肢体。
- [ ] 关键道具/动作有“预兆→执行→反应”；信息按既定顺序延迟揭示。
- [ ] 表演达到目标等级（主角镜至少 4 级，见 `32`）；眼神动态不缺失。
- [ ] 未擅自换衣、加情节、改空间、改数字；所有改动均已显式标注原因。
- [ ] 输出为纯文本分行、非表格；集尾按需要给出强钩子（`25`）。

交付：默认在对话中直接给纯文本分镜；开场用一两句说明本场场景数、镜头总数、总时长与光线处理。若为遵循用户约束做了道具/动作替换，必须在交付说明写明：原剧本是什么、改成了什么、为什么、二者是否互斥。不静默替换、不擅自降级；无法完成的部分明确说明缺口与所需输入。

## 环境备忘（Windows / PowerShell / .NET）

- Windows 环境 Bash 不可用，命令一律用 **PowerShell 工具**（`Get-ChildItem`、`Get-Content`、`Select-String`、`Copy-Item`、反斜杠路径）；macOS/Linux 用对应 shell 与工具。
- Python 可能已装但未必有 PIL/PyYAML；本 skill 自带脚本只用标准库。
- 无 PIL 时用 .NET 缩放图片（PowerShell）：

```powershell
Add-Type -AssemblyName System.Drawing
$src = [System.Drawing.Image]::FromFile("C:\path\input.png")
$newW = 1000
$newH = [int]($src.Height * $newW / $src.Width)
$bmp = New-Object System.Drawing.Bitmap($newW, $newH)
$g = [System.Drawing.Graphics]::FromImage($bmp)
$g.InterpolationMode = [System.Drawing.Drawing2D.InterpolationMode]::HighQualityBicubic
$g.DrawImage($src, 0, 0, $newW, $newH)
$bmp.Save("C:\path\output.jpg", [System.Drawing.Imaging.ImageFormat]::Jpeg)
$g.Dispose(); $bmp.Dispose(); $src.Dispose()
```
