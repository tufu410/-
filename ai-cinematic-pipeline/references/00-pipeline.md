# 00 · 管线总览（Pipeline Overview）

> 首次开工读本文件。目标：让任意一个剧本/创意/单镜头需求，都能沿着同一条可复现管线，产出风格统一、连续性可靠、可直接投产的图像与视频提示词。

## 1. 管线总图

```text
剧本/创意/参考图
      │
      ▼
[A] 建档盘点 ── 人物表 · 场景表 · 道具/信息载体清单 · 译名对照
      │
      ▼
[B] 图像资产 ── 角色设定表(Soul ID) → 场景静帧 → 道具表 → 精修/反打
      │            （视频的参考素材与首帧来源）
      ▼
[C] 分镜 ────── 通读剧本 → 按节拍拆镜 → 连续镜号/无缝时间码/七段工作稿
      │
      ▼
[D] 表演层 ──── 角色表演总档案 + 锁定声线（一次性）→ 逐镜单场适配
      │
      ▼
[E] 导演成品 ── 空间地图/首帧/调度 → 视场角/机位 → 物理/灯光/时间轴/对白
      │            产出英文视频提示词
      ▼
[F] 总质检 ──── 跨阶段一致性 + 各子系统清单 → 交付
```

四套子系统各司其职：

- **图像（Lira）**：解决“长什么样”——人物身份、场景空间、道具质感的静态资产。
- **分镜**：解决“怎么切”——镜头数量、顺序、景别、节奏、揭示顺序。
- **表演**：解决“人怎么活”——可拍摄的行为、眼神、声音、情绪阶梯。
- **导演（CINEDANCE）**：解决“怎么稳定生成”——空间/光学/物理/灯光/对白的硬锁定与防失败。

## 2. 各阶段输入 / 输出 / 参考文件

| 阶段 | 输入 | 产物 | 主要参考 |
|---|---|---|---|
| A 建档 | 剧本、人物小传、参考图 | 人物表、场景表、道具清单、译名 | `52-characters-scenes.md` |
| B 图像 | 人物表、场景表 | 角色三面板/设定表、场景静帧、道具表、精修图 | `10-image-prompts.md` |
| C 分镜 | 剧本（中英文台词）、参考图 | 七段骨架分镜工作稿（中文，纯文本） | `20`–`27` |
| D 表演 | 人物表、本场情境 | 角色表演总档案、声线提示词、各镜表演段落 | `30`–`32` |
| E 导演 | 分镜工作稿 + 表演段 + 参考资产 | 英文单镜头视频提示词 | `40`–`43` |
| F 质检 | 全部产物 | 修订后的成品 + 交付说明 | `53-final-qc.md`，`50`，`51` |

风格与视觉约束贯穿全程：光影色彩身份制见 `50-lighting-color.md`，负面阻断见 `51-negative-prompts.md`。

## 3. 三种典型入口

- **完整剧本（一集/多集）**：A→B→C→D→E→F 全走。先建档、产资产，再批量拆镜与填表演，最后逐镜出英文成品。
- **单个场景/镜头（“把这段写成视频提示词”）**：直接进 E，但动笔前在脑中快速过 D1 拆解、D2 诊断（见 `40`），并确认人物是否已有表演档案（没有则先补 D）。
- **单项资产（“做个角色表/场景图/道具/修这张图”）**：只走 B，按 `10-image-prompts.md` 的模型路由处理。
- **诊断/改写已有提示词**：进入对应子系统的质检清单（表演 `32`、导演 `43`、图像 `10` 的检查清单），定位问题再改。

## 4. 项目初始化：开工前建立四份档案

新项目开工，先内部建立并在需要时向用户补全（信息不足留空、不凭空编造外貌与数据）：

1. **人物表**：英文名｜中文称呼｜身份阵营｜年龄/体型/发型/肤色/眼睛｜标志服装配饰｜气质与习惯动作｜声线｜与主角关系｜情绪基调。反复出场者另建表演总档案（`31`）。
2. **场景表**：地点·日/夜·内/外｜空间结构与地标｜材质配色｜主光源方向｜对应参考图编号｜与前后场景是否同景。
3. **道具 / 信息载体清单**：关键道具、身份道具（轮椅/权杖/酒杯等）、把抽象台词绑定到的可拍物件；标注完好/破损/沾染等状态与归属角色。
4. **译名对照表**：中英文名一一对应；成品台词只用英文原名，不混写、不回译。

同时确认：画幅模式（9:16 / 21:9 / 16:9 / 1:1）、目标视频模型（Seedance/即梦/可灵/Runway/Pika）、目标图像模型、是否有固定风格锚点（胶片型号、摄影师参考、色调配比）。

## 5. 参考素材与 @标签管理

- 身份参考（面部/体型/年龄/比例/服装/唯一特征）、场景参考（建筑/材质/地理/氛围/地标/光源方向）、道具参考（外形/材质/手部接触/状态）、载具参考分开管理。
- 平台 @标签是原生参考索引，**原样保留、禁止自创**；每个写进提示词的 @标签必须对应当镜可见、需要加载的素材。
- 场景参考用于定义地理空间与材质，**不强行覆盖指定机位构图**（除非用户明确要求照搬）。
- 风格参考不得覆盖人物身份、空间调度、动作、光学、灯光。
- 读参考图：先缩到单边 ≤4000px、base64 ≤5MiB（超大图处理见 `20-storyboard-workflow.md`）。

## 6. 语言、画幅与交付约定

- 工作过程、分镜工作稿、交付说明用用户语言；**投产的图像/视频提示词正文与术语用英文**；台词用剧本英文原句。
- 画幅、分辨率、帧率、快门、模型名、随机种子是平台 UI 参数，**不写进提示词正文**；只在文档里提示用户去 UI 设置。
- 分镜工作稿纯文本分行、拒绝表格；镜号连续、时间码无缝（可用 `scripts/next_timecodes.py` 生成、`scripts/validate_storyboard.py` 校验）。
- 单镜头视频成品默认只输出英文提示词本身，不附推理/质检；用户要求分析时才给过程。
